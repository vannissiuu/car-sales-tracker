# 怎么把看板网址打开（GitHub Pages 开启指南）

这份指南写给完全不懂技术的人看。跟着下面的步骤点一遍，大概几分钟就能弄好。
只需要做**一次**，以后数据自动更新，网址不用重新设置。

---

## 第一步：打开仓库的 Settings（设置）

1. 打开你的仓库在 GitHub 网页上的页面。
2. 页面最上面一排有一行标签：Code、Issues、Pull requests、Actions、Projects、
   Wiki、Security、Insights、**Settings**——点最右边那个 **Settings**（设置齿轮图标）。
   （如果没看到 Settings，说明你的账号权限不够，找有权限的人来做这一步。）

## 第二步：找到 Pages 设置项

1. 进入 Settings 之后，页面左边有一排竖着的菜单。
2. 往下翻，找到 **Pages**（一般在"Code and automation"这个分组里）。
3. 点一下 **Pages**。

## 第三步：设置 Source（来源）

1. 页面中间会有一个 **Build and deployment** 区块。
2. 下面有个 **Source** 下拉框，默认可能是 "Deploy from a branch"——**保持这个不变，不用改**。
3. 下面会出现一个 **Branch** 选择区，有两个下拉框：
   - 左边的下拉框：选 **main**（或者你的仓库默认分支，通常叫 main 或 master）。
   - 右边的下拉框：默认是 `/ (root)`，点开它，**改选成 `/docs`**。
     （这一步最容易漏——一定要选 `/docs`，不能留在 `/root`，
     因为看板文件是生成在仓库的 `docs/` 文件夹里的。）
4. 点旁边的 **Save**（保存）按钮。

## 第四步：等它生效，然后拿网址

1. 保存之后，GitHub 会在后台开始"发布"你的页面，这个过程通常需要
   **1 到 10 分钟**（第一次开启可能稍微久一点，遇到高峰期也可能更久，正常现象）。
2. 过几分钟后，**重新刷新**这个 Settings → Pages 页面（不刷新可能看不到最新状态）。
3. 页面顶部会出现一行绿色的提示，类似：
   > Your site is live at `https://你的用户名.github.io/仓库名/`
4. 那一行里的链接，就是你的看板网址。点一下就能直接打开看板。
   建议把这个网址收藏一下，以后随时可以看。

## 之后会怎样：数据自动更新，你不用管

- 有一个自动化流程（sync）会定期去抓最新的销量数据，抓完存进仓库。
- 抓完数据之后，另一个自动化流程（build）会自动被触发，重新生成一份新的看板页面，
  自动提交更新到仓库的 `docs/` 文件夹。
- GitHub Pages 检测到 `docs/` 文件夹有更新，会**自动**重新发布，一般几分钟内网址上
  看到的内容就会跟着更新。
- 你唯一要做的事：**第一次**照着上面四步把 Pages 开起来。开起来之后，
  网址是固定不变的，以后打开同一个网址看到的永远是最新数据，不需要重新设置。

## 如果打开网址是空白页 / 404 / 一直没生效，怎么办

1. 先确认第三步里 **Branch 右边的下拉框选的是 `/docs`**，不是 `/ (root)`——
   这是最常见的出错点。
2. 确认仓库里已经真的有 `docs/index.html` 这个文件了（可以在仓库首页点进
   `docs` 文件夹看一眼）。如果这个文件夹还是空的，说明生成看板的自动化流程
   还没跑过或者跑失败了，需要找懂技术的人去 Actions 标签页里看一下运行记录。
3. 等待时间超过 15-20 分钟仍然没有变化，尝试在 Pages 设置页面里把
   Branch 下拉框先切回 `/ (root)`，点 Save，再切回 `/docs`，再点一次 Save
   （相当于重新触发一次发布，有时候能解决卡住的问题）。
4. 如果以上都试过还是不行，把 Settings → Pages 页面截图，找懂技术的人帮忙看。
