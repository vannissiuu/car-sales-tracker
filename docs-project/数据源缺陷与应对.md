# 数据源（车主之家 xl.16888.com）的三个缺陷，以及本项目的应对

**成文日期**：2026-09-14
**触发**：一次「8 月数据完整吗」的例行核对，牵出三个此前一直没被发现的数据源行为。

三个缺陷都不是本项目的 bug，是数据源自身的行为；但每一个都会让本项目的数据悄悄出错，
所以都必须在代码里主动应对。共同点是：**它们全都不会让流程报错，只会让数字变得不对。**

---

## 缺陷一：销量并列时排序随机 → 分页边界吞掉整款车

### 现象

31 个月里有 15 个月，`data/sales.csv` 出现「同一个月同一个车型名重复两行」，共 26 处。
**行数不变**（重复一条、丢失一条），所以总量对账完全查不出来。

### 实测证据

同一个页面 `style-202607-202607-10.html` 相隔几秒抓两次，销量都是 66 的三款车顺序完全不同：

```
第一次:  497 哈弗枭龙MAX(66)  498 凯迪拉克XT6(66)  499 阿维塔11(66)
第二次:  497 凯迪拉克XT6(66)  498 阿维塔11(66)     499 哈弗枭龙MAX(66)
```

**数据源对销量并列的车型没有稳定的次级排序键。**

### 机制

每页 50 条。当一组并列恰好骑在分页边界上，而抓第 N 页和第 N+1 页是两次相隔 2 秒的独立请求时：

```
2026-07 实例（菱智新能源 和 标致508 销量都是 62，正好第 500/501 名）：
  抓第10页那一刻：并列排成 [标致508(500), 菱智新能源(501)]  → 第10页末行拿到 标致508
  抓第11页那一刻：并列排成 [菱智新能源(500), 标致508(501)]  → 第11页首行又拿到 标致508
  结果：标致508 进了两次，菱智新能源 一次都没进
```

代码侧的缺陷：`fetch_full_listing` 逐页 `all_rows.extend(page_rows)` 无条件拼接，
**没有任何跨页去重或重叠检测**。

### 应对

**正确的不变式**：一份榜单本质上是「该月出现过的车型集合」，rank 只是偶然属性，所以
「**去重后的车型数 == 页面声明的共N条**」必须成立。

`fetch_full_listing` 里加了校验与修复：不平时由重复车型的 rank 反推分页边界，只重抓那一两页
（推不出边界形态就整趟重抓兜底），把集合里还没有的车型补进去，最多重试 3 次；3 次仍不平就
判定该榜单抓取失败，让 `sync_month` 放弃该月——**绝不返回一份已知有缺损的数据**。

`sync_report.md` 新增「## 分页完整性校验」小节，每个榜单一行，
**通过 / 修复 / 失败 / 跳过都记录，一次没触发也有正面记录**。

### 实际影响比最初估计的大

2026-09-14 全量重抓（force_refresh，54 分钟）的结果：

- 校验 224 个榜单：**187 个一次通过，37 个触发修复并成功，0 个失败，0 个月份被放弃**
- 补回的车型举例：飞度、凌派、雷凌、智己L7、仰望U9、创酷、科鲁泽、捷豹E-PACE、
  北京越野BJ60、菱智新能源、五菱荣光EV、捷达VA7……
- **37 > 最初查到的 26**：因为最初只扫了主榜的重复。**body 分类榜和新能源榜也在丢车型**——
  那些不会让 `sales.csv` 出现重复行，但会让车型的**车体类型和能源类型标错**。
- 重抓前后总行数、总销量完全不变（每处修复"删一条重复、补一条缺失"，净零），
  重复月份 15 → **0**。

## 缺陷二：车型改名会回填到历史页面

### 现象

数据源给某款车改名后，**它会用当前的名字重新渲染所有历史月份的页面**。
而本项目已经入库的行冻结在抓取当时的名字上，于是同一款车在图表里表现为
「一条线在某月断掉、另一条新线从下个月开始」。

### 实测证据

我们库里 2026-07 的车型「欧拉5」销量 4,069；今天去抓该站 2026-07 的榜单，
同一条记录的名字已经是「欧拉5 EV」，销量仍是 4,069。
**同月、同数、不同名。**

### 已知案例

| 旧名（我们抓取时） | 新名（数据源现在） | 改名时点 |
|---|---|---|
| 欧拉5 | 欧拉5 EV | 2026-08 前后 |
| 问道V9 | 极狐问道V9 | 2026-08 前后 |
| 星瑞FS21 | 星瑞L PLUS | 全量重抓时发现 |

### 应对

**全量重抓（`force_refresh=true, max_months=0`）会自动采纳数据源当前的全部车型名**，
从而一次性消除所有历史断线，不需要维护车型别名表。2026-09-14 那次重抓就是这么做的，
车型数 912 → 910（两处改名合并）。

代价是约 54 分钟、把数据源整个重爬一遍，且历史车型名会整体变一遍
（此前下载过的 CSV、发出去的截图会对不上）。**所以这是偶尔做一次的动作，不是常规手段。**

**排查方法**（不用猜相似度）：拿数据源当前的某个历史月份页面，
按**销量数值**（同月内几乎唯一）与我们库里该月的行做连接，销量相同、名字不同的就是确认的改名。

## 缺陷三：厂商归属会整条产品线迁移

### 现象

数据源会把某个厂商名下的车型整体挪到另一个厂商名下，甚至废弃整个厂商名。

### 已知案例

2026-08，「欧拉好猫」的厂商字段从「长城新能源」变成「长城汽车」。当时看起来只是这一款车挑窝
（两个厂商名在数据里都还活着），于是按 31 个月的历史一致性把它钉回了「长城新能源」。

2026-09 全量重抓后发现**这个判断的前提是错的**：欧拉芭蕾猫、欧拉闪电猫也一并挪到了「长城汽车」，
「长城新能源」名下只剩被我们自己按住的欧拉好猫。**数据源是废弃了整个厂商名，不是某款车挑窝。**

于是改为跟随数据源，统一归到「长城汽车」，厂商总数 117 → 116。

### 两处连带伤害

1. **`build.py` 会拒绝构建**。它有一条断言「同一车型只能属于一个厂商」，被打破时主动中止，
   宁可不出图也不出一张「统计范围」算错的图。**这次它做对了**——真正的失职是当时
   `continue-on-error: true` 把这声警报消了音（见 `自动部署说明.md` 第六节）。
2. **品牌会掉**。「长城汽车」是 `manufacturer_to_brand` 里故意设的**哨兵值**，含义是
   "此车型未分类，需要更新 `model_to_brand`"。车型挪过来之后就掉进哨兵，
   在品牌榜上以「长城汽车」的名义出现——2026-08 那次它一度排到了哈弗前面。

### 应对

- `data/mapping.json` 新增 `model_to_manufacturer`（车型名 → 应归属的厂商名，精确匹配，
  在解析品牌之前应用）。它既能纠正挑窝，也能**把存量行迁移到新的厂商归属**，
  不需要做一次几十分钟的全量重抓。
- `model_to_brand` 按**车型名**钉死品牌。这是双保险：**无论数据源以后把厂商字段怎么改，
  品牌都不会再掉**。欧拉好猫 / 芭蕾猫 / 闪电猫 / 欧拉5 EV 现在都钉住了。
- 两张表都要同时写进 `data/mapping.json` 和 `src/sync_script.py` 里内嵌的
  `DEFAULT_MAPPING_JSON`，两边不允许脱节。

## 配套：让 mapping.json 真正说了算

原先 `normalize_legacy_brand_column` 只给 **brand 为空**的行补值，已有 brand 的行永远不重解析。
而月份抓取是幂等的，所以**用户在 GitHub 网页上编辑 `mapping.json` 之后，已入库的历史行不会跟着变**
——README 里"下次同步自动生效"这句承诺对存量行是假的。

已新增 `normalize_brand_column`：把 brand 当成**每次运行都从 mapping.json 重新推导的派生列**，
逐行重解析、不同则覆盖。现在那句承诺是真的。

`sync_report.md` 里对应一行「品牌重解析：按 mapping.json 改写了 N 行的 brand」。

## 贯穿三个缺陷的一条教训

这三个缺陷加上同期发现的两个 workflow 问题（构建读旧提交、中止被吞成绿色），
**有一个共同点：故障发生了，但警报被消音了。**

- `continue-on-error: true` 把红染成绿；
- 行数对账掩盖了内容缺失（重复一条 + 丢失一条 = 行数不变）；
- 品牌哨兵值本来是用来喊"我没分类"的，但没人每月去看。

所以这一轮加的三道防线都是同一个思路：

1. **让检查在通过时也发出声音**——分页完整性校验即使一次没触发也要写一行"通过"；
2. **让失败真的变红**——去掉 `continue-on-error`，构建失败就不提交、推不上去就红；
3. **不让标签说谎**——新增产物一致性校验：`sales.csv` 的最大月份必须等于看板里写的
   「数据覆盖…至 X年Y月」，对不上直接失败且拒绝提交。

**沉默的检查等于没有检查。**

## 每月值得看一眼的三个数字

同步跑完后，在 `data/sync_report.md` 里看这三行：

| 指标 | 正常值 | 不正常说明什么 |
|---|---|---|
| 分页完整性校验：failed 的数量 | 0 | 有榜单重试 3 次仍不平，该月已被放弃 |
| 回退为厂商原值 | 0 行 | 有车型的厂商名不在映射表里，品牌归类不可信 |
| 车体类型覆盖率 | ≥ 90% | 某个 body 榜单没抓到，大批车型被归入「其他」 |

另外留意品牌榜里有没有出现**等于厂商名的品牌**（长城汽车 / 上汽集团 / 奇瑞捷豹路虎 /
星途 / 北京汽车制造厂 / 江汽集团 / 江铃集团新能源）——那是哨兵值在喊"这里有新车型没分类"。
