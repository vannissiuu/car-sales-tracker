## 四、已知的不确定性 / 推测部分（务必人工复核）

- 本脚本是在**完全无法访问 16888** 的环境下编写的，表格提取逻辑、编码猜测优先级、
  分页文字的正则表达式，全部是基于常见中文网站惯例的**推测**，没有被真实页面验证过。
- 如果 pandas/bs4 两种方式都没能提取到表格，大概率是页面把数据放进了 JS 变量而不是
  静态 `<table>`，或者列表实际上是 `<ul>/<li>` 结构——这种情况下请求本身是成功的，
  原始 HTML 已经存好了，需要人工重新设计解析逻辑，而不是本脚本能自动判断的。
- 编码判断优先用了 HTML `<meta charset>` 声明，其次 gb18030，最后才是 utf-8 兜底；
  **如果看到中文仍然是乱码，请直接查看 `*_raw.html` 原始字节对应的编码**，
  而不要相信本报告里 `chosen_encoding` 字段的猜测是100%正确的。
- “共XX条/共XX页”这类分页文字的正则是猜的常见写法，16888 实际用词可能不同
  （比如“共 500 款车型”“下一页”之类），`pagination_hints` 为空不代表页面没有分页信息，
  只代表没命中预设的几个正则，请打开 `_raw.html` 或 `_visible_text.txt` 人工搜索。
- 太平洋汽车 (`price.pcauto.com.cn`) 的 URL 路径是按经验猜测拼的，如果结构不对，
  大概率会拿到 404 或者一个跟销量无关的页面，需人工确认。
